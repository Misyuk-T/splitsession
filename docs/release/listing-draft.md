# Chrome Web Store listing texts

Texts for the one store item ([listing](https://chromewebstore.google.com/detail/splitsession-multiple-log/hhodioekcdmhpocjbkjnblmbmchddphf)).
Research, policy reasoning and sources: [chrome-web-store.md](chrome-web-store.md). **Section 2 is current**: the item is
updated in place to the Full build (decided 2026-10-27), and it has every text to paste for that update. Section 1 is the
Lite listing as published up to 0.1.x (history, and the base the new texts grew from).

Rules these texts follow (sources in chrome-web-store.md, sections 1 and 2):

- The store shows the manifest `name` as the title and the manifest `description` as the short summary (132 characters max).
  If the dashboard text differs from the manifest, the manifest wins on the card, so **edit `wxt.config.ts` `EDITIONS`
  rather than the dashboard** when a title or summary changes.
- No lists of third-party brand names, no "best/#1/free", no repeated keywords, no testimonials. Site names appear at most
  as one plain example ("two accounts of the same site"), never in the title or summary.
- Every permission justification says what the permission does **for the user** and what it is **not** used for.
- No claim the code does not back up (e.g. "works with every site"): limits are stated in the description and FAQ.

### Long description

```
SplitSession brings Firefox-style containers to Chrome. Keep several accounts of the same website signed in at the same time, in different tabs of one Chrome profile: a work and a personal account, two client accounts, a test account next to your real one. No second profile, no second browser, no incognito juggling.

HOW IT WORKS
• Create a container: a name and a colour. Tabs you open in it get their own cookies and their own site storage.
• Sign in to a site in one of them, then sign in to the same site as someone else in another. Both stay signed in.
• Links and pop-ups opened from such a tab stay with it, so sign-in pop-ups work.
• Other tabs are ordinary Chrome tabs, with your usual logins.

FEATURES
• Create, rename, recolour and delete containers (8 colours).
• Separate cookies, localStorage, sessionStorage, IndexedDB and Cache Storage for each one.
• Optional Chrome tab groups in matching colours; dragging a tab into a group moves it there.
• Site rules: "always open this site in Work" or "ask me".
• Container tabs come back in their containers after a browser restart or Reopen closed tab. If SplitSession cannot tell a tab's container for sure, the tab waits in the popup instead of opening with the wrong login.
• Close a container's tab group to free up space: its tabs are remembered, and one click in the popup brings them all back.
• Export and import your setup as a JSON file (cookies are left out unless you tick a clearly marked box).
• Light and dark themes, full keyboard support.

PRIVACY
• Everything stays on your device. SplitSession has no servers, no account, no analytics and sends nothing anywhere.
• Container cookies are stored locally in SplitSession's extension storage on your device. They are never sent to a SplitSession server, and there is none.
• Open source (MIT): the full code is on GitHub.

GOOD TO KNOW
• SplitSession separates logins; it is not a VPN, an anti-fingerprinting tool or a sandbox. Sites still see the same browser and the same IP address. Do not use it to break a site's rules about multiple accounts.
• Service workers (offline mode, push notifications) are switched off in isolated tabs, so those features work only in normal tabs.
• The first page of a tab that SplitSession did not open itself loads with your normal profile before the tab is moved. Open tabs from the SplitSession button or with a site rule for a clean start.
• Google sign-in: start it from the site you are signing in to, inside the isolated tab, and do not add a site rule for the Google sign-in page itself.
• The full list of what is and is not isolated is in the documentation (docs/limits.md on GitHub).

PERMISSIONS, IN SHORT
Chrome will say SplitSession can "read and change all your data on all websites". That is needed to give each tab its own cookies on whatever site you open in it. SplitSession reads cookie headers only of tabs you put in a container, keeps them on your device and never sends them anywhere.

Source code, issues and documentation: https://github.com/Misyuk-T/splitsession

SplitSession is free and open source. If it helps you, you can support development at ko-fi.com/tomashdev.
```

### Permission justifications (dashboard, one field per permission)

| Permission | Justification (paste as is) |
| --- | --- |
| `declarativeNetRequest` | For tabs the user has put in a container, session rules replace the Cookie request header with that container's own cookies and remove Set-Cookie from responses, so the container's logins never mix with the regular profile. One static rule answers SplitSession's own content script locally. No ads or content are blocked. |
| `webRequest` | Observes (does not block or modify) the response headers of container tabs to read Set-Cookie before the declarativeNetRequest rule removes it, and stores those cookies in that container's local cookie jar. Requests of tabs that are not in a container are ignored. |
| `scripting` | Registers SplitSession's own bundled content scripts at document start, and only while the user has containers, so that document.cookie, localStorage, IndexedDB and similar page storage are kept separate per container. No remote code is loaded or injected. |
| `tabs` | Tracks which tab belongs to which container, opens and reopens tabs in a container, keeps pop-ups and links opened from a container tab in the same container, and reads a tab's address to apply the user's domain rules. |
| `tabGroups` | Optionally shows each container as a Chrome tab group with the container's name and colour, and keeps group and container in sync when the user renames, recolours or drags tabs between groups. |
| `storage` | Stores containers, domain rules, settings and each container's cookies locally on the user's device (chrome.storage.local). Nothing is synced or sent off the device. |
| `webNavigation` | Detects when a tab starts navigating to a site that has a domain rule, so the page opens in the right container before the first request, and checks who started a navigation so that web pages cannot move tabs between containers. |
| `browsingData` | Used only with the "serviceWorkers" data type: removes service workers of sites used in containers (and, in the optional strict mode, of all sites), because a service worker's requests bypass per-tab isolation and would leak the regular profile's logins into a container. No history, cookies or other browsing data are removed. |
| `alarms` | Runs short periodic maintenance in the background service worker: removes expired cookies from container jars (every minute) and re-checks tab-group membership (every 30 seconds, only when tab groups are on). |
| `sessions` | Recognises a tab or window the user reopens (Reopen closed tab, History, restore after restart) so that a container tab comes back in its container instead of opening with the regular profile's logins. |
| Host permission `<all_urls>` | Containers work on whatever site the user opens in a container tab, so the cookie header rules and the storage-separation script need access to any site. SplitSession acts only on tabs the user has put in a container (plus removing service workers of those sites); it does not read or change pages in normal tabs and sends no data anywhere. |
| `cookies` (optional) | **Remove before submission**: the code never calls `chrome.cookies` (see the findings at the top of chrome-web-store.md, and Purple Potassium in its section 3). If it is kept, the field needs a real use. |
| Remote code | Answer **"No, I am not using remote code."** All JavaScript is in the package; no eval, no new Function, no remotely loaded scripts. |

### Privacy practices: data usage (Lite)

Tick (reasoning in chrome-web-store.md, 1.4):

- **Authentication information**: yes (container cookies are handled and stored locally).
- **Web history**: yes. The user-data FAQ counts cookies in browser storage and HTTP request and response content as

- **Website content**: no. All other categories: no.
- Certify all three statements: not sold to third parties; not used or transferred for purposes unrelated to the single
  purpose; not used to determine creditworthiness or for lending.

## 3. Privacy policy (draft summary, both editions)

**Written: [../privacy.md](../privacy.md)** (the outline below is what it follows). It is published at a stable URL through GitHub Pages of the repository (`/docs`, `/privacy`), one page with a section per edition.

1. **Who**: SplitSession, an open-source project by Taras Misiuk; contact e-mail (the developer account's verified
   contact address) and the GitHub issues link.
2. **What the extension handles**: container definitions, domain rules, settings; cookies that sites set in container
   tabs (to keep each container signed in); the addresses of tabs (to apply domain rules and restore container tabs);
   a local diagnostic log (Full: agent tool name, tab ID, site, ok/error, time; never page content or typed text).
3. **Where it is kept**: only in `chrome.storage.local` on the user's device, unencrypted, like Chrome's own cookies.
   Not synced, not backed up by the developer, removed when the extension is uninstalled.
4. **What leaves the device**: nothing, ever, from the extension. The developer runs no server and receives no data,
   analytics, crash reports or telemetry. Export files are created only when the user clicks Export and are saved
   where the user chooses; cookies go into an export only when the user ticks the box that says so.
5. **Full edition, agent bridge**: off by default. When the user switches it on, page content, screenshots, tab titles
   and addresses that the user's own local agent asks for are passed to the companion program on the same computer
   through Chrome native messaging, and from there to that agent. What the agent does with them is governed by the
   agent's own terms (e.g. an AI provider the user chose). SplitSession does not send them anywhere itself.
6. **No sale, no transfer, no advertising, no credit decisions**; use of data is limited to the single purpose
   (Chrome Web Store Limited Use statement, quoted with a link).
7. **Children**: not directed at children.
8. **Changes**: dated versions in the repository's history; material changes announced in the release notes.
9. **Effective date**.
